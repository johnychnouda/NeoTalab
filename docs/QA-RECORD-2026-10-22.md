## Environment and safety

- **Lab only.** API on `127.0.0.1:8011`, website on `localhost:3011`, a separate SQLite file
  database, the stand-in AI (`AI_DRIVER=fake`), and a stand-in for Meta's WhatsApp API that records
  every outgoing message (`qa/mock_graph.py`). Google, OpenAI, email and backup keys were blanked.
- The servers already running on ports 8001/3001 and the local MySQL settings were left untouched.
- Lab logins were random and stored only in the git-ignored lab folder. No password is in this document.
- Limits of the lab: SQLite runs writes one at a time, so race tests are **less faithful than
  production MySQL** (races that pass here may still race on MySQL). One background job failed
  with "database is locked", which is a SQLite artifact.

## Decisions and observations

1. **Done (owner decision, 23 Oct): existing shops repaired.** A one-time database update
   (`2026_10_23_000000_fill_missing_business_kind_settings`) runs on deploy and fills only the missing
   business-type settings from each shop's type; anything a shop set itself is kept. Test:
   `test_existing_shops_get_their_missing_business_settings_once`.
2. **Done (owner decision): checkout charges today's price.** The receipt and the saved order read
   the current item, size, extras and offer prices (`CartService::refreshPrices`). Test:
   `test_checkout_charges_todays_price_not_the_price_when_added`; live: 9 × 1.25 became 9 × 2.00.
3. **Done (owner decision): deleting a shop deletes its data**: menu, orders, customers, chats,
   bookings, team, logins and their sessions (`AdminMerchantService::delete`). Problem alerts stay,
   unlinked from the shop. Test: `test_deleting_a_shop_removes_all_its_data_and_nothing_else`; live: nothing left.
4. No way to create shop admin or shop staff dashboard logins (roles exist, unused).
5. The customer's WhatsApp profile name is not saved, so reports show phone numbers only.
6. A typed checkout through the AI does not save the address for next time (button checkout does).
7. Team staff can mark a cancelled booking as completed or no-show (no status check).
8. Opening a shop's dashboard from the owner portal ("impersonate") gives an 8-hour login and is not
   written to the activity log.

## D. How to run these tests again

Automated (no setup needed, nothing outside is called):

```bash
cd backend && php artisan test && ./vendor/bin/pint --test
cd web && npm test
```

Lab (throwaway database; never production). Needs PHP, Python 3, Node.

```bash
qa/setup_lab.sh                      # creates qa/.lab (git-ignored): database, random lab logins
```

Then start four processes (in the desktop app: `.claude/launch.json` entries, or terminals):

```bash
python3 qa/mock_graph.py qa/.lab/graph.jsonl                        # stand-in WhatsApp API, port 8019
qa/.lab/lab.sh php artisan serve --host=127.0.0.1 --port=8011       # lab API
qa/.lab/lab.sh php artisan queue:work --sleep=0.2 --tries=3         # lab queue (restart after code changes)
```

The lab website: copy `web/` elsewhere with `NEXT_PUBLIC_API_URL=http://127.0.0.1:8011/api/v1`
in its `.env.local`, then `next build && next start -p 3011`.

Run the suites in order (each prints PASS/FAIL; results go to `qa/.lab/results.jsonl`):

```bash
cd qa && python3 s01_setup.py && python3 s02_catalog.py && python3 s03_authz.py
python3 s04_stock_race.py 10 && python3 s04b_stock_race5.py
python3 s05_journey.py && python3 s06_webhook.py && python3 s07_salon.py
python3 s08_customers.py && python3 s09_owner.py
node first_login.mjs rest            # sets the restaurant's own password in the browser
./e2e_env.sh npx playwright test --project=setup --project=desktop-chromium --workers=1
./e2e_env.sh npx playwright test --project=setup --project=phone-chromium --workers=1
node xss.mjs qa-manakish-corner
```

Keep the computer awake and plugged in for browser runs. Use `--workers=1` (one login is shared and
the API allows 120 requests a minute per login). Cleanup: stop the processes and delete `qa/.lab`.
