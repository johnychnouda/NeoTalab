# QA record, 21 October 2026 (branch `qa/exhaustive-audit-2026-10-21`)

Scope: the NeoTalab API and database, run against the disposable lab API (127.0.0.1:8001) and the
lab database `scratchpad/lab/r2.sqlite`. Production was not touched. No real messages were sent and
no payments were made in these tests.

## Discovery (Phase A)
- 93 API routes, 23 models, 44 migrations, 14 jobs, 18 web pages.
- Backend: 42 feature test files and 3 unit test files (PHPUnit, run with `php artisan test`).
- Web: 2 test files (Vitest). No Playwright, no lint and no type checking in the web project.
- No end-to-end browser tests exist in the repository.

## Results so far

| Phase | What ran | Result |
|---|---|---|
| B1 | `authz_matrix.py`: anonymous access, shop owners on platform pages, impersonation, cross-shop reads/writes/deletes on products, categories, zones, drivers, variants, bookings, customers, orders, mass assignment | 48 passed, 0 failed |
| B2 | `role_matrix.py`: shop staff vs shop admin vs shop owner on manager-only actions | 16 passed, 0 failed |
| D | `invalid_input.py`: malformed product data (missing name, negative price, text price, 5000-character name, null body, array body, unknown field, script in name) | 8 passed, 0 failed |

Notes on these results:
- One check of `/orders` returned 404. There is no orders API route (orders are WhatsApp-only), so that check was my mistake, not a defect. It was removed.
- Two early cross-shop checks were wrong: they used the wrong shop's login. They were corrected and rerun.
- The script-in-name check proves only that the request is accepted or refused. It does not prove the page shows the text safely. That belongs to the browser tests in Phase C.
