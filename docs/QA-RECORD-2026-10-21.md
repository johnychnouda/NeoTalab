# QA record, 21 October 2026 (branch `qa/exhaustive-audit-2026-10-21`)

Scope: the NeoTalab API and database, run against the disposable lab API (127.0.0.1:8001) and the
lab database `scratchpad/lab/r2.sqlite`. Production was not touched. No real messages were sent and
no payments were made in these tests.

## Discovery (Phase A)
- 93 API routes, 23 models, 44 migrations, 14 jobs, 18 web pages.
- Backend: 42 feature test files and 3 unit test files (PHPUnit, run with `php artisan test`).
- Web: 2 test files (Vitest). No Playwright, no lint and no type checking in the web project.
- No end-to-end browser tests exist in the repository.

Notes on these results:

- The script-in-name check proves only that the request is accepted or refused. It does not prove the page shows the text safely. That belongs to the browser tests in Phase C.

## Phase C: browser tests (Playwright, added on this branch)
Files: `web/playwright.config.js`, `web/e2e/` (`auth.setup.js`, `helpers.js`, `public.spec.js`, `dashboards.spec.js`).
Test logins are read from environment variables (`E2E_OWNER_EMAIL`, `E2E_OWNER_PASSWORD`, `E2E_SHOP_EMAIL`, `E2E_SHOP_PASSWORD`, `E2E_SHOP_SLUG`) and are not stored in the repository.

| Command | Target | Result |
|---|---|---|
| `E2E_BASE_URL=http://localhost:3001 npx playwright test --project=setup --project=desktop-chromium` | local production build, 1280x800 | 32 passed, 0 failed |
| same, `--project=phone-chromium` (Pixel 5) | local production build, 393 px | 32 passed, 0 failed |
| `npx vitest run` (existing unit tests) | web | 10 passed |

What the browser tests check: each public page loads without a server error or a page-level error, and has no sideways scroll; the join form refuses to continue without a shop name; Arabic sets the page to right-to-left and French to left-to-right; the owner portal's main pages and settings tabs load; the inbox has no "mark as paid" text; the shop dashboard's main pages load; all seven shop settings tabs open.

What they do NOT check yet: most buttons, forms and dialogs; Arabic and French versions of the dashboards; the full join flow; Firefox and Safari (only Chromium is installed).

## Finding while writing the browser tests
- The login is rate limited. Repeated sign-ins in quick succession show "Too Many Attempts". This is intended protection. The browser tests now sign in once per account and reuse the session.
- The shop sign-in page and the shop dashboard share the same address, so a test must wait for the password box to disappear, not for an address change.
