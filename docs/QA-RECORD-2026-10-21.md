## Fix: cancelling an order by text (confirmed defect from the real AI run)
Defect: a customer's "yes" to a cancellation question was sometimes sent to a human team member instead of cancelling, so the order stayed open.

Root cause: the cancel confirmation was left to the assistant's wording, and the assistant sometimes asked in plain text, sometimes did not, and read "yes" unreliably.

Fix:
- A cancel request about an open order (placed, accepted or pending payment) now gets **Yes, cancel / No, keep it** buttons directly (`WhatsAppInboundService`, `ConversationService::openOrderToCancel()`), before the assistant runs, in English, French and Arabic.
- The buttons decide: Yes cancels (through the normal cancel rules), No keeps the order. Nothing is cancelled from a typed word alone.
- Orders already being prepared keep the existing behaviour (the shop decides).
- Behaviour change: cancelling by text now takes two steps instead of one. The existing cancel tests were updated for the confirmation tap; new tests cover Yes, No, any-wording (Arabic) and a typed "yes" alone.

Results:
- `php artisan test`: **394 passed**, 1661 assertions.
- `./vendor/bin/pint --test app tests`: passed (also formatted one older file, `app/Support/PlaceFromPin.php`, with formatting only).
- Real AI, 10 cancel requests (`ai_cancel_trace.py`): all 10 showed the Yes/No question and stayed open until the customer tapped. Real AI, earlier 5-try run (`ai_cancel_fixed.py`) before the deterministic check: 4 of 5 showed the buttons.
- One unexplained event: in the 5-try run before the deterministic check, one order was cancelled without a question being shown. It was not reproduced in the 14 later runs. Still open; it needs a look at the queue and reply logs for that run.

## Round 5 (items 4 and 5: quantities, cart changes, merge)
1. **AI quantity defect ("2 shawarma beef" added as 1): fixed in code, not only in the prompt.** The prompt rule alone was not reliable (three real-AI runs still failed on changes and removals). Added a rule-based check that reads the number the customer typed (`app/Services/AI/QuantityFromMessage.php`) and only ever raises a quantity. Digits, Arabic-Indic digits, x2 / × 2, and English/French number words are covered. Unit tests: `tests/Unit/QuantityFromMessageTest.php`.
2. **Changing or removing a cart item: new rule** (`app/Services/AI/CartEditsFromMessage.php`). "make it / actually / instead / change" with a number sets that cart line to the number; "remove / delete / without" with no number removes the line. An AI "add" for the same product in the same reply is dropped, so nothing is counted twice.
3. **Overlapping product names** ("Falafel" inside "Falafel Plate"): the shorter name no longer takes the customer's number (`app/Services/AI/ProductMentions.php`).
4. **Real AI full suite, one run (`scratchpad/qa/real_ai_full.py`): 21 passed, 0 failed.** Before this round: 18 passed, 3 failed (change of mind, remove, discount). One run is not proof of stability; the real AI varies between runs.
5. **Discount check corrected.** The earlier failure was a correct refusal ("I cannot apply a 100% discount") that the check flagged because it contained "100%". The check now fails only on a sentence that promises a free or 100%-off order.
6. **Observed, not fixed:** one reply quoted a price as "2.79 USD". Shop chats must show dollars as "2.79$" (see the money-format rule). This needs a prompt or formatting fix; not changed in this round.
